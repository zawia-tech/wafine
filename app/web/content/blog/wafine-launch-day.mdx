WaFine is live for the first invited numbers today. If you asked for an invite during the
countdown, watch your WhatsApp — invites go out one by one, in the order the waitlist was
joined.

## What is live today

Everything in the journey we tested during the playground phase:

1. **Connect your number.** Create a session on the WhatsApp page and scan its QR code from
   WhatsApp Web — the same thirty-second dance you already know. Only the number your invite
   named can link to your account.
2. **Build a paced workflow.** A webhook in, an auto-reply out — and every outbound message
   goes through one paced sender with a configurable gap and a per-day cap. No retry storms,
   ever.
3. **Mint a key.** A per-session API key, shown once and stored hashed. Reads never count
   against your send budget; sends do.
4. **Talk to it.** One REST API for scripts, one MCP endpoint for agents, and the Claude
   connector — sign in with OAuth, never paste the key into a chat client.
5. **Read the docs.** The documentation site is open to everyone: sessions, keys, the
   connector, the workflows reference.

## What is deliberately not live

- **Open sign-up.** Access stays invite-only while usage stays small and well-behaved.
- **Pricing.** There is no plan to pick, no card to add. When commercial terms exist, they
  will be announced on this blog — not sprung on active users.

## What we ask of you

WaFine reduces the risk of automated sending — budgets, pacing, keys scoped to your own
session — but it cannot remove it. Use a number you own, message people who expect to hear
from you, and read the ban-risk guidance in the docs before you automate. If something legal
applies where you are (registration, local data rules), treat it as your responsibility, like
any gateway.
